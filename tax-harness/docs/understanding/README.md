# 项目理解导读

依据2026年11月4日的运行代码0.4.0，提交bab7940整理。本次只增加说明、图和证据提取脚本，不改变业务行为。

建议按下面顺序阅读：先理解一次请求经过哪里，再跟踪一次保存，最后看失败怎样发生。

1. [架构图与模块职责](architecture.md)：入口、模型、业务工具、数据库和返回路径。
2. [调用链路与状态变化](call-chains.md)：查缺项、修改保存、跨会话恢复，以及绕过模型的按钮和管理命令。
3. [13个真实失败案例](failure-cases.md)：原始输入、实际回答、工具证据、根因分析与修复边界。
4. [提取后的原始证据](../../reports/analysis/failure-evidence.json)：报告及日志SHA256、行号、工具结果和模型原始输出。

这里的“失败”指已有验收真实记录的失败，不把正常权限拦截、主动故障注入当成新增产品缺陷。13个失败case来自两次连续测试，其中包含连锁失败，不代表13个独立根因。

## 一句话理解

用户自然语言进入ChatSession，由同一个qwen3:8b提出工具调用；Python校验并执行，工具结果再交回模型组织回答。确认保存、页面资料刷新、偏好按钮、规则管理和备份恢复都可以直接走程序，不需要模型。

当前没有第二个“检测模型”，也没有bge-m3向量检索链路。跨会话记忆是SQLite中的结构化任务与偏好，不是把全部聊天重新发给模型。

## 产出物分别是什么

| 位置 | 含义 | 是否是业务当前值 |
| --- | --- | --- |
| tax_harness/ | 实际运行代码；static/是网页 | 否 |
| data/source/ | 原始比赛材料副本，只用于导入和核对 | 否 |
| data/business.sqlite3 | 当前发票、流水、规则、任务、偏好和审计 | 是 |
| data/traces/ | 实际使用时的模型、工具与状态日志 | 证据，不是自动恢复的记忆 |
| reports/ | 模拟测试结果、日志和截图；历史失败也保留 | 否 |
| backups/ | 业务库快照及校验清单，不上传Git | 备份时刻的值 |
| docs/stages/ | 各阶段实现与使用说明 | 否 |
| docs/understanding/ | 本次架构、链路及失败分析 | 否 |
| Git阶段标签 | 可恢复的代码版本；不包含日常数据库 | 否 |
