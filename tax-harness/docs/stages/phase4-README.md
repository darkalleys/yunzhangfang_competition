# 第四阶段 本地可视化与故障验证

日期：2026年11月4日。程序版本0.4.0。新增本地浏览器工作台，复用第三阶段的模型、权限、数据、记忆和规则工具，没有增加运行时Python依赖或数据库表。

## 如何启动

最简单的方式是在项目目录双击 `web.cmd`，保持终端窗口运行，打开 http://127.0.0.1:8765 。停止时在终端按Ctrl+C。

也可在tax-harness目录运行：

```powershell
python -m tax_harness init
python -m tax_harness web
```

Ollama需要已启动并安装qwen3:8b；数据面板和偏好管理不需要模型推理，发送自然语言消息才会调用模型。原有start.cmd和chat.cmd继续可用。

若从第二阶段升级旧数据库，先执行 `python -m tax_harness migrate`，会自动备份。已有第三阶段数据库无需再次迁移。端口被占用时可指定 `python -m tax_harness web --port 8766`。

重复演示建议使用独立数据库：

```powershell
python -m tax_harness --db data/web-demo.sqlite3 init
python -m tax_harness --db data/web-demo.sqlite3 web
```

演示库文件名若已经使用过，会保留其已有修改；换一个新文件名才会重新导入原始数据。

## 页面能做什么

1. 选择演示用户、企业和业务月份，点击进入会话。身份不是实际账号登录，沿用比赛的U001/U002模拟权限。
2. 顶部显示当前数据库的发票合计、银行收入和支出。
3. 左侧自然语言查询、用途检查、用途及备注修改草稿；也可点击快捷问题。
4. 草稿明确标注尚未保存，点击确认保存后执行原有保存与回读流程。取消按钮丢弃草稿。
5. 数据页查看发票与银行明细；任务页查看恢复进度、删除任务、设置或删除明确偏好。
6. 规则页查看当前企业的版本、状态、正文和生效日期，含停用版本用于核对。并非所有列出的版本都适用当前业务月，实际回答以业务工具选择的版本为准。规则导入及启停继续通过本地管理员命令完成。
7. 记录页查看企业修改审计和当前会话最近60条模型/工具事件，可展开查看实际输入与结果。完整日志保存在本地data/traces下。
8. 重新进入会话后恢复持久任务和偏好，草稿和修改授权不恢复。浏览器刷新不恢复旧聊天气泡。

用户、企业或月份改变后会关闭旧会话并清空页面，必须重新进入，避免界面范围与实际操作范围不一致。确认保存请求还要匹配当前草稿的操作编号；失效草稿不能提交。

网页确认按钮代替手动输入/confirm，偏好表单代替/pref等命令。输入框仍兼容旧控制命令，当前没有把普通自然语言“确认”解释为保存授权。

## 已验证的结果

- 60项程序测试通过，新增HTTP来源与路径校验、会话隔离、过期草稿确认、并发请求拒绝、偏好管理、长对话和保存后任务刷新失败处理。
- 实际使用本机Microsoft Edge无头浏览器和真实qwen3:8b验收，覆盖页面查询、草稿未保存、确认回读、同号隔离、恢复、偏好删除、只读用户、无权限企业、规则、日志、范围切换及手机宽度无横向溢出。
- 最终网页验收15项、长对话与故障恢复5项均通过。批次路径、结果与截图索引见 [第四阶段验收记录](../../reports/phase4/README.md)。
- 对实际桌面和手机截图进行了视觉检查，浏览器验收保存截图与结果JSON。
- 真实模型在12轮额外交流后仍能继续用途任务，重新查询并排除另一个会话已经填好的F002。
- 可控模拟模型离线后，旧草稿清除且F003没有被修改；恢复真实模型连接后正常查询，重开会话任务仍保留。
- 发票已经保存但后续任务刷新失败时，明确提示“保存已完成，任务刷新失败”，不再笼统声称保存失败。
- 旧版本代码及数据恢复演练的5项检查继续通过。

本轮测试环境为Windows、Python 3.14.7、Microsoft Edge及Ollama qwen3:8b。早期阶段的Python3.13.5验证记录仍保留。本轮自测使用隔离临时数据库，未对默认业务库执行业务写操作。

模型及浏览器证据按批次保存在reports/phase4/，每批有result.json及相关日志/截图；旧阶段报告不覆盖。真实模型的最终回答措辞可变化，验收不代表任意自然语言都正确。

## 验证命令

```powershell
python -m unittest discover -s tests -v
python scripts/verify_web.py
python scripts/verify_phase4.py
python scripts/verify_recovery.py
```

verify_web.py会创建临时本地服务和隐藏Edge实例，完成验收后退出。浏览器驱动使用标准库与Edge DevTools协议，不是应用运行依赖；该脚本当前仅支持装有Edge的Windows。verify_phase4.py模拟离线的是该测试进程的请求，不会停止用户的Ollama服务。

## 五分钟演示顺序

- 第1分钟：选择U001、甲企业、2026年9月，查金额、缺项并展示规则版本。
- 第2分钟：给F002补用途，生成草稿后更正，点击确认保存，再看发票、审计和剩余四张缺项。
- 第3分钟：设置偏好、重新进入会话，展示任务恢复及当前数据，然后更正、删除偏好。
- 第4分钟：切换乙企业看不同门槛，再选择U002展示只读权限和乙企业访问拒绝。
- 第5分钟：展开实际模型输入、工具结果与保存回读，说明模型与程序分工及当前不足。

页面实际操作会改变所选数据库，请使用独立演示库。模型等待时间要计入演示总时长。

## 维护、回滚与边界

本阶段不改数据库结构，继续使用第三阶段增量迁移和备份工具；代码标签为phase4-v0.4.0，第三阶段标签phase3-v0.3.0保留。业务数据库、备份和日常私有日志不上传Git；提交的浏览器与模型证据均来自比赛模拟数据。

服务仅监听127.0.0.1，具备来源和会话校验，定位为本机比赛演示。没有生产账号认证、远程部署或多人公网服务能力。同一会话并发操作会拒绝；空闲两小时的会话会失效，活动会话上限64，重新进入恢复持久任务。页面规则维护仍用本地CLI。

当前只把最近4轮完整消息和结构化任务/偏好加入模型输入，最多保留8轮会话对象，未实现完整聊天历史恢复或精确token计量。客户端请求或提交后回读的复杂故障仍须进一步增强，当前不会自动重试写入操作。

下一阶段建议围绕交付完善：整理2至3页设计说明、固定演示脚本和演示数据，增加更广泛的自然语言回归及提交后状态核对，复查主办方截止时间和压缩包限制，最后录制不超过五分钟的演示。
